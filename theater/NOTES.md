# NOTES —— 公开版设计决定

> FROZEN 数据边界见根目录规格；本文只记录可公开复用的实现理由，不记录作者作品、私有批次或机器环境。

## 多工具协作（v1.6）

- `AGENTS.md` 是 Codex 原生入口兼工具中立共同规则；`CLAUDE.md` 导入它。Codex 与 Claude Code 各自保留原生角色/skills，AGY/CodeBuddy 作为无状态外部执行器。
- model 记录真实底层模型，transport 记录执行通道。工具名不能冒充模型名。
- 并发不是项目常量；按当前运行时、限流和额度分波，并给编排方保留质检与 collect 能力。

## 数据三层与写入纪律

- corpus 是作者资产；theater 是可替换代码；results 是随时间累积的账本。
- reads 与 votes 均 append-only；纠错通过 sidecar 的 hidden/void 标记完成，不删除历史。
- 跨进程锁覆盖“读现状、分配 ID、校验、写入”整个事务。只锁最后的 append 仍会产生重复 ID，因此不采用。
- collect 先完整校验再整批写入；任何一条失败都不允许形成半批状态。

## 投票身份与信号分流

- 主动票与跟帖顺势票代表不同强度的信号，来源必须分开保存和统计。
- 主动方向票以 target + persona 为业务身份；model 只记出处，换模型重试不会制造第二张票。
- 同值重试跳过，冲突重试整批拒收。best 是相对票，以 ballot_id 表示“这一张候选票面”，允许不同票面再次选中同一评论。

## 跟帖模式

- 跟帖只从已有长评开楼，回复只看到祖先链与自己的历史，避免全楼上下文把讨论压成同一种声音。
- 引用 parent 的承重句必须逐字可核对；引用失败不落盘。沉默是正式回执，不要求模型为了显得投入而硬说话。
- 跟帖不评分，`score=null`，不进入榜单或校准。人格版本、深度、立场变化、沉默与 void 使用专属 sidecar。

## Persona 与用户侧车

- 随发行附带的人设放在 theater 下；用户新增、改写和隐藏的人设放在 corpus 侧车。升级代码时不会覆盖用户选择。
- 人格可跨文体复用，但判断标准需随体裁转换；非诗文体必须由用户显式加入阅读池。

## 校准原则

- LLM 不做跨作品排名；榜单只由盲读账本的代码计算视图产生。
- 校准需对低样本收缩，并诊断不同模型拿到的作品池是否失衡。失衡越大，映射越靠近恒等，避免把选样偏差误判成读者严宽。
- 非诗与诗歌使用不同判断标准，不共享同一排行榜量表。

## ZIP 更新安全边界（v1.6）

- 只信固定的官方公开仓库地址；限制下载和解压大小，拒绝路径穿越、重复路径与符号链接。
- 只更新明确允许的代码、静态资源、测试和公开文档；corpus、results、settings、batches 不在允许清单。
- 覆盖前备份，替换失败则回滚。Git 仓没有 upstream 时明确拒绝，不自动拿公开 ZIP 覆盖开发现场。

## 掌中册只读边界（v1.7）

- 电脑的 corpus/results 仍是唯一真源；移动快照在请求或导出时自动派生，不维护第二份数据文件。
- 同一套无构建前端服务于桌面、PWA 与单 HTML 留影，不另抄 APK 页面。
- 手机服务默认关闭，随机配对口令逐次轮换且拒绝全部 POST；二维码在本机生成。
- 手机收藏、最近阅读与私人随记仅存在手机浏览器，并按 poem id 叠加到新快照；电脑刷新不会覆盖它们。
- Tailscale Serve 只作为可选私密 HTTPS 通道；公开 Funnel 不进入产品教程。
- 局域网扫码是浏览器入口加本轮只读口令，不是持续 socket 或设备证书；页面只在打开或手动更新时拉取快照。
- 局域网 IP 与私密域名属于不同浏览器 origin；不绕过同源隔离，跨入口迁移走显式导出与合并导入。
- 词云仍只给 120 个词计算例句和共现；完整词频另用轻量 ranking 下发，避免把全词表带入二次方共现计算。
- 跟帖暂不按楼层数或票数伪造“激烈度”，等定义出可审计的讨论信号后再增加索引与筛选。
